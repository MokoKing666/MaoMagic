### 关键踩坑记录（重要）

1. **AGP 9 内建 Kotlin** —— AGP 9.0 起内建 Kotlin 支持并默认启用，
   Android 模块**必须移除** `org.jetbrains.kotlin.android` 插件，否则报
   "The 'org.jetbrains.kotlin.android' plugin is no longer required for Kotlin support since AGP 9.0"。
   同时 `jvmTarget` 默认取 `android.compileOptions.targetCompatibility`，无需显式声明。
   纯 JVM 模块仍用 `org.jetbrains.kotlin.jvm`。

2. **`Theme.DeviceDefault.DayNight.NoActionBar` 不存在** —— 需在
   `values/themes.xml` + `values-night/themes.xml` 分别用
   `android:Theme.Material.Light.NoActionBar` / `android:Theme.Material.NoActionBar`。

3. **`io.github.kyant0:backdrop` 的 CMP 依赖不是冲突** —— 依赖树里会出现
   `org.jetbrains.compose.*:1.12.0`，但缓存中**只有 .pom + .module，没有 .aar/.jar**，
   是纯元数据重定向，不产生重复类。无需 resolutionStrategy/exclude。

4. **Compose 1.12 无公开的 `CornerBasedShape.minCornerRadius`** ——
   lens 的 height 上限需自行从四角 `CornerSize.toPx(size, density)` 求最大值。

5. **backdrop 的两种 backdrop 语义不同（架构关键）**：
   - `rememberCanvasBackdrop { }` → 不录制内容（isCoordinatesDependent=false），
     **任意位置安全**，用于内联玻璃
   - `rememberLayerBackdrop { drawRect(bg); drawContent() }` → 录制内容图层，
     可真实折射页面内容，但**被 layerBackdrop 标记的子树内绝不能出现引用同一 backdrop 的 drawBackdrop**
     （录制与读取互引 → 渲染死循环 → SIGSEGV in RenderThread）
   - 因此 MagicBackdrop 拆成 `content` 与 `overlay` 两个平级插槽

6. **lens 的硬性前提**：shape 必须是 `CornerBasedShape`（RoundedCornerShape 满足），
   否则库会抛 UnsupportedOperationException。API 门槛：RenderEffect ≥ API31、
   RuntimeShader（lens/gammaAdjustment）≥ API33 —— 这是 minSdk 定为 33 的原因。

### 真机联调：抓到并修掉两个真 bug（用户报 + 我发现的）

用户报：「点 Tab 页面会跳转过去但下面的气泡不会」。

**Bug 1：点 Tab 气泡不动**
- 根因：`remember(selectedTabIndex)` **以 lambda 为 key**。
  `MagicScaffold` 传的是 `{ selectedTab }` —— 捕获的是 **Int 值**。值一变，
  Compose 就必须重建 lambda → key 变化 → `remember` 重新初始化 →
  **生成新的 `MutableIntState`**。
  而 effectB 的 `snapshotFlow { currentIndex }` 绑定的是**旧 state 对象**，
  它此后永不变化 → 气泡再也不动。页面走的是另一条路径（外部 tab 状态直接变），
  所以照常跳转。**这解释完全吻合用户的描述。**
- 诊断过程：先排除「Animator 时长缩放」（实测 1.0）；vivo 限制了应用日志，
  `Log.i` 抓不到；改用**像素测量**定位气泡（找 accent 蓝色像素中心），
  再**逐行 diff 官方原版**确认我移植的代码无误 → 定位到调用方。
- 修复：① `LiquidBottomTabs` 去掉 `remember` 的 key（state 对象生命周期内恒定）
  ② `MagicScaffold` 用 `rememberUpdatedState` 让传下去的 lambda **实例稳定**

**Bug 2：课盘显示「戊戌月 · TU旺」「癸亥日 · SHUI」**
- 根因：领域枚举未重写 `toString()`，默认返回**枚举常量名**，被字符串插值漏到界面
- 修复：9 个领域枚举统一重写 `toString()` 返回中文标签

### 关键发现（我主动查出来的）
**README 写着「没有网络权限」，这是不实陈述。**
用 `aapt2 dump permissions` 核实 release APK：**确实声明了 INTERNET 与 ACCESS_NETWORK_STATE**
—— 脚手架阶段就写进 manifest 了，而当时没有任何代码用它。
已改成如实描述。这类「文档与事实不符」的问题必须主动查、主动改。

### 实现
- `CloudAiConfig`：默认 enabled=false、baseUrl/apiKey/model 全空。四者缺一 → isAvailable=false → 链落 Tier1 → **零网络流量**
- `ChartPrompt`：把**已排好的**卦盘渲染成提示词。系统提示词明确写「绝对不要自己重新排盘」——
  排盘由本地确定性算法做（一定准），模型只负责论述。这是 Tier2 是「解释器」不是「排盘器」的原因
- `CloudAiInterpreter`：任何异常（网络/超时/鉴权/JSON）都返回空 Flow → 链自动降级，
  用户永远拿得到结果，不会看到报错页
- `SecretStore`：API Key 走 Android Keystore + AES-GCM。**不进 MagicSettings**——
  那个 data class 会被序列化成明文 JSON 落盘

### 踩的坑
1. **OkHttpClient 不能做公开构造函数的默认参数**：OkHttp 是 `implementation` 依赖，
   类型一旦出现在公开签名，消费模块编译就报 `Cannot access class 'okhttp3.OkHttpClient'`。
   改成私有主构造 + 公开次构造。
2. **Android 库模块的单元测试任务名是 `testDebugUnitTest` 不是 `test`**，
   且测试目录要放 `src/test/kotlin`（放 `src/test/java` 也能编译但不被识别）。
   core:ai 是 android.library，core:interpret 是 kotlin.jvm，两者不同。
3. `InterpreterChain.interpret()` **直接返回结果**（内部已 firstOrNull），不是 Flow。
   梅花页残留了 `.firstOrNull()`，编译报错才发现。
4. 拒绝做 SSE 流式：链用 `firstOrNull()` 取结果，流式会被截断成第一段。
   要流式必须同时改链与 UI，不在本次范围——在代码里写明了这个判断。

## 2026-10-17 续5 · 黄历支持任意日期（用户提问引出的缺口）

### 用户问「有了日运月运是不是不需要黄历了」

但这个问题暴露了真实缺口：**黄历只能看今天**。
而 `CalendarService.of()` 本来就支持任意日期，是 `AlmanacScreen` 里
`remember { CalendarService.today() }` 把日期写死了 —— 纯 UI 问题。

- 黄历保留，与日运明确分工

- 日运/月运也支持切换日期（复用 MagicDateBar，月运用 MONTH 粒度）
- **两条去重规则**：日运不列宜忌（那是黄历职责）；今日干支只在黄历出现一次

### 实现
- 新增 `MagicDateBar`（前后翻 + 输入 + 回到今天，支持 DAY/MONTH 粒度）
- **日期算术一律用 `java.time.LocalDate.plusDays/plusMonths`，绝不手写 ±1 天**

- 黄历标题「今日黄历」→「黄历」；时柱行注明「随当前时辰」
- 底部加「查看我的今日运势」动线（日运未实现时按 available 隐藏，不做死按钮）

**返回钮压住页面标题** —— 返回钮是浮层、不占布局，

### 现象
点「设置」立即闪退回桌面。**logcat 里没有 FATAL EXCEPTION 栈**，

`drawBackdrop(backdrop, effects = { lens(…, chromaticAberration = true) })`，

**多层折射 → 渲染线程崩**。设置页是唯一用滑块的页面，所以只有它崩。

（此前轨道还用了 `layerBackdrop(trackBackdrop)` 录进独立 backdrop，

1. 去掉轨道的 `layerBackdrop` + `rememberCombinedBackdrop`

### 教训
**玻璃组件组合数是有上限的。** 单个 `drawBackdrop` 没问题、
`GlassCard` 嵌在 `MagicBackdrop` 里也没问题，但再加一层带 `lens(chromaticAberration)`

### 三条铁律（**重要，与我踩的坑完全吻合**）
1. 容器圆角一律用 `MagicSmoothCornerShape`（连续曲率），不用 `RoundedCornerShape`（正圆弧）。
   例外：胶囊类用 `percent = 50`。
   手柄默认 0.6040（smoothing 0.35）；0.7 是上限，0.821 会让圆角读成方形。
2. 同心圆角 `r_child = r_parent − padding`，圆心必须重合。
   例：卡片 28dp / padding 16dp → 内控件 12dp；分段控件容器 12dp / padding 2dp → 滑块 10dp。

## 2026-10-17 续21 · 结果卡四维条改两极分布（未真机验证）

## 2026-10-17 续31 · 六爻闪退根因：Modifier.weight(0f)

### 根因
上一轮改表头时我写了 `MagicHeaderCell("六神", weight = 0f)`。
Compose 的 `Modifier.weight` 内部 `require(weight > 0)`，
**传 0f 在组合阶段抛 IllegalArgumentException**。

表现极具迷惑性：
- 六爻页本身能进（卦盘还没渲染）
- 一旦起卦/载入示例卦让 HexagramCard 出现 → **立刻闪退**
- 编译期完全不报

### 为什么拖了两轮才发现
前两轮我用估算坐标点「载入示例卦」都没命中，
拍到的桌面被误判成「截图时机不对」。**实际是崩了。**
教训：**界面点完回到桌面 = 大概率是崩了，不是时序问题。**
第一时间就该 grep `FATAL EXCEPTION`，而不是怀疑坐标。

### 修法
定宽列不走 weight：`Text(..., modifier = Modifier.width(YaoWidth.SHEN))`。

### 真机验证（水地比 · 六四动，通过）
盘面布局与通行排盘一致：
`六神 | 六亲+支+五行 | 干支·世应 | 爻符 | 动爻标记 | 爻符 | 变卦六亲`
- 世应压进行内（「戊子 · 应」「乙卯 · 世」）✓
- 动爻标 ×，位置正确（六四 = 自下而上第四爻 = 腾蛇行）✓
- 变卦侧补全（子孙亥水 / 丁亥）✓
- 六爻自下而上 ✓
- 零崩溃

### 通用教训
**`weight` 必须 > 0。** 要「不参与权重分配」的列用 `Modifier.width`，
不要用 `weight(0f)` 取巧。这类错误只在运行时的特定界面炸，
单测和编译都拦不住 —— 所以**改了布局必须看到那个界面**才算完。

## 2026-10-17 续32 · 铜钱改成一爻一摇（六摇成卦）

### 原来
`castByCoin()` → `Divination.byCoinRandom()` —— **一次摇出六爻**。
结果一样但没仪式感。

### 改法
1. VM 新增 `throwOneCoin()`：每次掷三枚，累加一爻，摇满六爻才建盘。
   **`Divination.byCoin(throws)` 本来就支持累积**，内核一行没动。
2. 按钮文案跟爻位走：摇初爻 → 摇二爻 → … → 六爻已齐
3. 进度提示「已摇 N / 6 爻」
4. 铜钱显示 `3 2 3` → `字 背 字`（数字是内部记法，字背才是摇卦时看到的）

### 真机验证（通过）
摇满六爻，爻位名/和数/老少/字背全对，按钮变「六爻已齐」，盘面正常，零崩溃。
这一卦六爻全静（无 6/9），概率约 17.8%，属正常。

### 踩坑
第一次连点 6 次坐标没生效，换 3 个不同 y 才成功 —— 屏幕滚动了，
之前按固定坐标算的位置失效。**别假设页面没滚动过**。

### 六爻这块到此完整
- 盘面：六神 | 六亲+支+五行 | 干支·世应 | 爻符 | 动爻 | 爻符 | 变卦六亲

## 2026-10-17 续33 · 摇一摇 + 翻转动画（音效未做）

### 摇一摇（新文件 ShakeDetector.kt）
**用加速度计不用陀螺仪**：摇动是平移加速度变化，陀螺仪测角速度，
握着手机晃不一定有明显转动。加速度计对「摇」更敏感、误触更少。

- 净加速度 = |a| − GRAVITY_EARTH，超阈值才算摇动
- **防抖 700ms 必须有**：一次摇动连发多帧，不加会一摇连出好几爻
- 摇满六爻后 enabled=false 停监听
- 无加速度计的设备静默降级到按钮，不报错
- `onShake` 用 `rememberUpdatedState` 包一层，否则监听器持有旧 lambda

### 动画
太极图 `rotationY` 翻 360°（480ms FastOutSlowIn）。
**翻面不是旋转** —— 铜钱是翻面。

### 音效：明确不做
需要音频资源。程序合成的 WAV 是电子蜂鸣，不是铜钱落桌声。
**拿它冒充音效不如没有。** 要真做得要真实音源或授权素材。

### ⚠️ 两个未决问题
1. **摇一摇无法用 adb 验证** —— `input` 造不出加速度事件，只能真机手摇。
2. **疑似误触发**：测试时只点 2 次却显示已摇 6 爻。
   怀疑 `SHAKE_THRESHOLD = 18` 偏低，被环境振动触发。
   待真机调，建议 18–25。

### 教训
传感器类功能**没有 adb 验证路径**，交付时必须明确告知「未经真机验证」，
不能让用户以为测过了。
