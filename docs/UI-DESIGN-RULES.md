# UI 设计规则

> 本文件是「猫仙幻术」视觉实现的**约束清单**。每条规则都对应一个可验证的判据，
> 不是审美偏好。修改设计系统前请先读完。

---

## 一、五条硬规则

### 1. 可读性高于一切

任何材质、折射、渐变，一旦使文字变得含糊，就必须退让。

| 项 | 阈值 |
|---|---|
| 正文 / 次要正文 | 对比度 ≥ 4.5 : 1 |
| 大字（≥ 24sp Regular 或 ≥ 18.66sp Bold）与图标 | ≥ 3 : 1 |
| 交互控件边界、Tab 选中指示 | ≥ 3 : 1 |
| 字号下限 | 正文/注释 ≥ 13sp，图例/角标 ≥ 12sp。**禁止 11sp 及以下** |
| 法律 / 免责声明文案 | ≥ 13sp |

**玻璃表面不透明度 0.62 是实测底线。** 低于它，正文在浅色玻璃上的有效对比度会跌破 4.5:1。
玻璃质感靠 `blur(24dp)` + 高饱和保住，**不是**靠降低不透明度。

### 2. 只允许两层玻璃，且不得相邻嵌套（No Glass on Glass）

```
L1  CONTENT  内容卡片
L2  OVERLAY  悬浮控件（Tab 栏、弹窗、导航栏、浮动按钮）
```

- L1 卡片**内部**的控件（分段控件、按钮、输入框）一律**实心填充**
- 需要同时存在时，内层用 ≥ 0.72 alpha 的实色，或统一包进一个容器
- 违反后果：层级塌陷（看不出什么浮在什么之上），且每多一层就是一次全屏纹理拷贝 + shader 采样

实现上由 `MagicSolidButton` / `MagicSegmentedControl` 提供实心替代品。

### 3. 同心圆角

```
r_child = r_parent − padding
```

两个圆心必须在同一坐标点，否则接缝处出现可见的厚度跳变。

| 元素 | 半径 | 内边距 | 子元素半径 |
|---|---|---|---|
| 标准卡片 | 28dp | 16dp | **12dp** |
| 大卡片 / 弹窗 | 36dp | 16dp | **20dp** |
| Tab 栏外壳 | 32dp | 8dp | **24dp** |

Tab 栏的选中指示器高度取 48dp ⇒ 胶囊半径 = 48/2 = 24dp ⇒ 与上式恰好相等。
**改动任一项数值都必须重新核对这个等式。**

同时：`lens()` 折射要求 `shape` 必须是 `CornerBasedShape`。

### 4. 颜色永不单独承载语义

约 8% 男性存在红绿色觉障碍；且「红 = 危险」在西方语境下与中式吉凶约定相反。

因此吉 / 凶 / 警示一律使用**颜色 + 字形**双通道（见 `MagicSemanticMark`）：

| 语义 | 字形 | 浅色 | 深色 |
|---|---|---|---|
| 吉 | ✓ | `#B03A3E` | `#E0757A` |
| 凶 | ✕ | `#2F6B5C` | `#5FAF95` |
| 警示 | ⚠ | `#B26A00` | `#E0A44A` |

**默认中式约定**：吉 = 红、凶 = 绿（与欧美交通 / 金融习惯相反）。

### 5. 背景必须低饱和且有细节

流体玻璃靠**折射背景**成立。纯色背景上做玻璃，与一块实色卡片视觉上毫无区别。

因此背景层必须同时具备：

- 低饱和基调 + 缓变线性渐变
- 大半径低饱和色斑（提供色相变化与纵深）
- **高频细节层**（极低对比度的爻线阵列 + 细颗粒噪点）—— 给 `blur` 提供可处理的输入
- 卦纹底纹（语义细节）

细节层对比度必须 ≤ 4%，否则会读成可见纹理干扰内容。

**背景绘制必须屏幕锚定**：`Backdrop.drawBackdrop` 的绘制发生在玻璃表面自身的局部坐标系里，
若直接在局部坐标画渐变，每张卡片都会得到自己尺寸对应的一份渐变，
同一屏内不同卡片透出的底色就会不一致（ΔE 很大）。

### 6. 深色主题的玻璃表面**必须用白抬升**，绝不能用黑

这是本项目最容易写错的一条。

```kotlin
// ❌ 错：黑叠在暗背景上 → 卡片比背景更暗
val surfaceBase = if (isLight) Color.White else Color.Black

// ✅ 对：一律用白；亮色靠"遮"、深色靠"抬"
val surfaceColor = Color.White.copy(alpha = surfaceAlpha)
```

| 主题 | 表面色 | 机制 | 数值 |
|---|---|---|---|
| 亮色 | 白 | **遮住**背景，保证正文 ≥ 4.5:1 | 0.62（卡片）/ 0.72（密集） |
| 深色 | 白 | **抬升**表面；可读性由 backdrop 自身不透明保证 | 0.08（卡片）/ 0.11（覆盖层） |

**两者机制不同，数值不可互换。** 亮色需要高不透明度去遮；深色只需要一点点提亮。

写错会怎样：卡片读作「在页面上挖了个洞」，而不是「抬起的面板」——
层级整个反过来。iOS 深色模式的抬升表面是**更亮**的。

**推论**：「密集数据要更不透明」这条在深色下**不能**翻译成「抬得更高」。
抬得越高，浅色文字的对比度越低。密集表格的边界清晰度应由内描边 + 顶边高光负责。

深色下改抬升幅度时，`tertiaryText` 必须同步重算 —— 卡片一亮，浅色三级文字就会跌破 AA。

### 7. 容器圆角用 `MagicSmoothCornerShape`，不用 `RoundedCornerShape`

`RoundedCornerShape` 生成的是**正圆弧**：一段 90° 圆 + 两条直线，
在「弧 ↔ 直线」接点处曲率从 `1/r` 直接跳到 `0`。

`MagicSmoothCornerShape` 每个角一段三次贝塞尔，端点落在两条直边上、手柄沿直边延伸
（与直边 G1 连续）。手柄系数：

```
handle = 0.5523 + (0.70 − 0.5523) · smoothing
smoothing = 0.35 → handle 0.6040 → 径向偏差 2.6%  （默认）
```

手柄上限刻意压在 0.70 而非 1.0：0.82 时径向偏差达 14%，圆角会读成「方形」。

**必须继承 `CornerBasedShape`** —— 这是 `lens()` 折射的硬性前提。

**例外**：胶囊类（`tabBar` / `pill`）保持 `RoundedCornerShape(percent = 50)`。
胶囊端部本来就定义为半圆，不做平滑。

> **诚实的边界**：这不是苹果原始曲线的逐点复刻（苹果未公开参数）。
> 它解决的是**族**的问题 —— 让圆角离开「正圆弧」这一族。
> 在 28dp 尺度上偏差约 2.5px @3.5x，属于「更顺，但说不出哪里不一样」的量级。

### 8. 效果调用顺序：`vibrancy()` 必须在 `blur()` **之前**

库源码里 `chain()` 的实现是：

```kotlin
android.graphics.RenderEffect.createChainEffect(
    other.asAndroidRenderEffect(),   // ← 外层
    this.asAndroidRenderEffect()     // ← 内层（先作用于像素）
)
```

即**后调用的在外层**。所以：

```kotlin
vibrancy()          // color filter
blur(24.dp.toPx())  // 包在外层
```
= `blur(colorFilter(source))` ⇒ 色滤**先**作用于像素 ⇒ 符合库文档要求的
`color filter ⇒ blur ⇒ lens` 顺序。✅

反过来写 `blur(); vibrancy()` 会得到 `colorFilter(blur(source))`，
色滤被挪到 blur 之外，**违反**库的强制顺序。不要"顺手调换"。

## 二、间距与排版

**间距严格 8pt 栅格**：8（行内）/ 12（卡片之间）/ 16（屏幕边距、卡片内边距）/ 24（区块）/ 32（大区块）。
禁止 5 / 7 / 13 / 17 等非 8 倍数值。

**字号阶梯**：34（大标题）/ 22（卡片标题）/ 17（正文、行内强调）/ 15（次要正文）/ 13（注释）/ 12（图例）。

## 三、性能约束

| 约束 | 原因 |
|---|---|
| 禁止 `LazyColumn` 逐项 `drawBackdrop` | 每项都要复制背景 + 跑 RenderEffect，滚动严重掉帧。列表整体包一层 |
| 玻璃叠层 ≤ 2 | 每层一次全屏拷贝 + shader 采样 |
| blur ≤ 24dp，lens ≤ 48dp | 采样开销随半径超线性增长 |
| 提供 `glassMode` 降级开关 | `FULL` / `REDUCED`（仅 blur）/ `OFF`（高不透明实色） |
| 尊重系统无障碍设置 | 读取「减少动态效果」「降低透明度」自动降级 |

## 四、崩溃防线（backdrop 库的三条铁律）

违反任意一条都会崩溃或使效果失效。

| # | 规则 | 违反后果 |
|---|---|---|
| 1 | 必须调用 `Modifier.layerBackdrop(backdrop)` | 效果完全不生效 |
| 2 | **绝不允许在 `drawBackdrop` 之后再加 `layerBackdrop`** | 渲染死循环 → `Fatal signal 11 (SIGSEGV) in RenderThread`。嵌套玻璃必须改用 `exportedBackdrop` |
| 3 | 底色要先 `drawRect` 进 backdrop | 玻璃边缘出现透明像素 |

### 两种 backdrop 的语义差异（架构关键）

| | `rememberCanvasBackdrop` 等价物（环境折射源） | `rememberLayerBackdrop`（内容折射源） |
|---|---|---|
| 内容录制 | 不录制 | 录制内容图层 |
| 可用位置 | **任意位置安全**（含 `LazyColumn` item 内） | 被 `layerBackdrop` 标记的子树内**禁止**引用同一 backdrop |
| 折射能力 | 只能折射环境背景 | **可真实折射页面内容** |
| 用途 | 内联玻璃（卡片、列表、按钮） | 覆盖层玻璃（Tab 栏、弹窗、导航栏） |

因此 `MagicBackdrop` 拆成 `content` 与 `overlay` **两个平级插槽**：
内联玻璃走环境折射源，覆盖层走内容折射源。这样既拿到真折射，
又从结构上避免了引用环导致的崩溃。

### 兜底：backdrop 必须无条件先铺一层不透明底色

坐标在首帧或宿主不可用时可能拿不到。若此时直接 `return`，玻璃会退化成
「透出下层内容」的半透明块，卡片与弹窗会彻底失去边界。

**实测教训**：设置弹窗曾整片透出底层页面内容，原因就是坐标未就绪时 backdrop 什么都没画。

#### 本轮我自己修掉的真 bug

**深色模式卡片方向反了**（对方在 4.3-2 提出怀疑，我实测确认）

- 证据：深色截图中卡片比背景**更暗**，读作「挖了个洞」
- 根因：`MagicGlassSurface` 写 `if (isLight) White else Black`，
  深色下「黑 0.60」叠在暗背景上必然更暗
- 修复：表面色**一律用白**；深色只做轻微抬升（0.08），
  可读性由 backdrop 自身不透明保证 —— 见硬规则 6
- 连带：卡片抬升后 `tertiaryText` 会从 4.78:1 掉到 3.99:1，
  同步提亮 `#8E8271 → #9E9280`（4.7:1）

#### 已核实：对方一条建议是错的

对方在 4.3-1 建议「把 `vibrancy()` 挪到 `blur()` 之后再试一次」。
**这条不能采纳** —— 会违反库的强制顺序。

核实过程（读库源码）：
```kotlin
// com.kyant.backdrop.internal.RenderEffect.kt (androidMain)
createChainEffect(
    other.asAndroidRenderEffect(),   // 外层
    this.asAndroidRenderEffect()     // 内层（先作用）
)
```
后调用的在外层 ⇒ `vibrancy(); blur()` = `blur(colorFilter(src))` ⇒ 色滤先作用 ⇒
**正是**库文档要求的 `color filter ⇒ blur ⇒ lens`。当前顺序是对的。
详见硬规则 8。

## 六、平台认知（重要）

**「参考 iOS 27」不等于「拥有 iOS 27 的系统能力」。**

本项目是 Compose 跑在 Android 上。iOS 上由框架强制绘制、开发者碰不到的东西
（选中胶囊、材质合成、safe area 语义），在这里全部要自己实现、自己验证。

- iOS 26+：**不要**自绘选中胶囊，交给系统（框架强制绘制，覆盖会被忽略，自绘会叠成两层）
- Android / Compose：**必须**自绘，几何必须自己算对

**几何精度是自绘方案唯一的护城河 —— 算错了没有系统帮你兜底。**
